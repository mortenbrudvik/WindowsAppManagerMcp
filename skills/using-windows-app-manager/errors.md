# When Something Fails

Read this when a result has an `errorCode`, a `status` or a `warning` that the index in [SKILL.md](SKILL.md#other-error-codes) does not settle, or a tool, a window or a capture is missing.

[SKILL.md](SKILL.md#codes-that-mean-stop) lists the codes that mean stop; their full entries are here too. The codes of the browser tools are in [browser.md](browser.md); of the capture and OCR tools in [screens-and-ocr.md](screens-and-ocr.md#screenshots); of the layout tools (`MonitorNotFound`, `InvalidPresetFile`) in [layouts-and-monitors.md](layouts-and-monitors.md).

## Window Selectors

Any tool given `window`; nothing was done:

- `AmbiguousWindow`: several windows match, and `candidates` lists up to 5 (handle, title, processName, processId, className; `isAgentHost` marks your own terminal or editor, or, when the error says a marked candidate may be another app's, any window of a program that started before the server), front to back. Never repeat the same selector and never just take the first candidate: pick the one the user means and call again with `window: {"handle": ..., "processId": ...}`, or narrow the selector (`titleEquals`, `titleRegex`, `processId`, `className`). Do not turn a candidate's position into `index`: z-order can change before the next call. If you cannot tell which one the user means, ask.
- `WindowNotFound`: nothing matches. Check with `find_windows`: `processName` is the whole name, and cloaked (other virtual desktop) and untitled windows need `includeCloaked` or `includeUntitled`. With `foreground: true`, the window in front is not the one the filters describe.
- `HandleMismatch`: the handle now belongs to another window (the one you meant closed), or the window changed while the call waited to run. Find the window again; do not retry the handle.

## Input Refusals

The `errorCode` of `mouse_click`, `drag`, `mouse_move`, `scroll`, `type_text`, `send_keys`, `press_keys`:

- `TargetIsAgentHost`: the input would have reached your own terminal or chat window. Pass `windowHandle` with the window you mean. When the error says the window counts as the host's only because the server cannot read its ancestor processes, it may be another app's window, and naming it does not help: tell the user (`get_server_info` warns about it). Until it can, `isAgentHost` can mark such windows, `popupsExcluded` and `windowsExcluded` can count their popups and windows, and a close's `ProtectedWindow` says the same.
- `TargetNotForeground`: the target could not be brought to the front (`receivingWindow` is what is in front instead). Call `focus_window` to see why, or ask the user.
- `TargetOccluded`: another window covers the point (or no window is there). Bring the target to the front with `focus_window`, or take fresh coordinates from `get_ui_elements`.
- `BlockedByModal`: a modal dialog (`blockingWindow`) disables the target, or opened while typing (`charactersTyped` says how much was typed). Read the dialog (`respond_to_dialog` with its handle and no `button`) and decide deliberately, or ask the user; act on it by its handle.
- `TargetLostFocus`: another window came to the front before or while the keys were sent; `charactersTyped` says how much was typed. Check the field before typing the rest.
- `DestructiveChordNeedsTarget`: `send_keys` with a chord that closes, quits or locks needs `windowHandle`. To close a window, use `close_window`.
- `KeysAfterFocusChange`: `send_keys` had more keys after a chord that hands the keyboard to another window (Alt+Tab `%{TAB}`, Alt+Esc, Ctrl+Esc, `{WIN}` or a Windows-key chord such as `#r`, Alt+Space, or a closing chord). For the character #, write `{#}`. Make that chord the last key and send the rest in a new call; better, pass the other window's handle as `windowHandle` instead of switching with Alt+Tab.
- `CursorNotAtPoint`: the mouse pointer did not stay at the point (a game or remote session holds it, or the user is moving the mouse), so nothing was clicked. Try once more; if it repeats, ask the user.
- `CursorClamped`: not a refusal: the click, move or scroll was sent, but right after it the pointer was elsewhere (`actualX`, `actualY`), so it may have landed there. Look (a capture or `get_ui_elements`) before you send it again; do not simply retry.
- `MouseInUse`: a mouse button is held down, or another window has captured the mouse (the user is dragging or selecting, or a menu is open), so a click or move would go to that window (or the capture could not be read, for example because a window just closed). Wait until the user has finished, or close the menu, then retry. A button that stays down although nobody is pressing it (stuck) keeps every click and move refused, and `release_all_input` releases only buttons the server pressed: ask the user to press and release that mouse button.
- `WheelFollowsFocus`: `scroll` was refused because the user's Windows setting sends the wheel to the focused window, and the window at the point is not in front. Call `focus_window` on it, then scroll again.
- `TextTooLong`: `type_text` types at most 5,000 characters and pastes at most 1,000,000; `send_keys` sends at most 5,000 keys (and is `InvalidArguments` when its `delayMs` waits would add up to more than 10 seconds: lower `delayMs` or split the keys). Paste long text (`method` `paste` or `auto`), or send it in parts.
- `PauseChordNotAllowed`: the keys would press the user's pause hotkey (with `type_text`, also a character typed with AltGr, or a paste's Ctrl+V); nothing was sent. Only the user presses it: never look for another way to send it. `type_text` with `method: "unicode"` presses no keys for its characters.
- `UserInterrupted` (`type_text`, `drag`, `run_steps`, with takeover detection set to stop): the user used the keyboard or mouse while it ran, so it stopped there and released what it held; part may have been sent. Do not try again at once: ask the user before you go on. A `warning` that takeover detection did not work means the user's input was not watched then: check the result.
- `ClipboardUnavailable`: `type_text` with `method: "paste"` could not lend the clipboard: it holds formatted text, an image, files or a password manager's private copy, which could not be put back, or another app held it open. Nothing was pasted and the clipboard is unchanged. Type the text (`method: "unicode"`), or ask the user to clear the clipboard.
- `TargetInMenuMode`: a menu is open, so `type_text` would pick menu items. Close it with `send_keys` `{ESC}` (with `windowHandle`) or click into the field.
- `TargetElevated`: the window runs as administrator; Windows would drop the input. Ask the user to do the step. You can tell beforehand: `list_processes` marks such a process `aboveServer: true`, and so does `get_window_info` with `detail: "full"` for its window.
- `TargetDeniedByPolicy`: the user does not allow the agent to act on or read that app (by default password managers, the Windows credential, elevation and SmartScreen prompts, and Windows Security). No argument changes it, not even `force` or `forceKill`: ask the user to do the step. `element_action`, `respond_to_dialog`, `file_dialog`, `close_window`, `close_windows_batch`, `close_application`, `kill_process`, `capture_window`, `capture_with_elements`, `focus_window` and the other window tools (move, resize, state, snap, the batches, `apply_layout`, `restore_workspace`) refuse such apps the same way, and so do the UI Automation reads (`get_desktop_state`, `get_ui_elements`, `find_ui_elements`, `read_element_text`, `read_table`, `wait_for_element`, `get_active_popups`, `get_focused_element`, `get_element_at_point`), even for a window you name; a `desktop` or `windowAndPopups` search leaves such windows out. Inside an allowed window, an element of a denied app's process (an embedded WebView2, a preview, another app's child window) is refused by ref and left out of walks, searches (`truncationReason` `PartsSkipped`) and table cells, with a warning that names the process (for a walk, a `TargetDeniedByPolicy` warning); `element_action` or `read_element_text` criteria that match only such elements are `TargetDeniedByPolicy`, and next to an allowed match `AmbiguousElement`; `wait_for_element` never matches them. When the warning names a helper such as `msedgewebview2` or `prevhost` and the user allows only some apps, tell the user: it must be listed too.
- `SessionLocked`, `DesktopUnavailable`: the screen is locked or a UAC prompt is shown. Wait for the user.
- `PausedByUser`: the user paused input with the pause hotkey, or the server paused itself (the error says so). Stop and ask the user (see [Safety Rules](SKILL.md#safety-rules-read-first)). One press of the hotkey does not resume a server that paused itself, and while a server cannot read the shared pause, the hotkey reaches it only if that server registered the chord; a confirmed `resume_input` does (`get_control_status` says what the hotkey does there).
- `ModifiersHeld`: Shift, Ctrl, Alt or Windows is down (`heldModifiers`), so keys would become shortcuts and clicks Ctrl-clicks. The user may be typing: wait a moment and retry. Pass `releaseHeldModifiers: true` (or call `release_all_input` with it) only when nobody is pressing the key, because it releases the user's key too. While one of the keys is a modifier of the pause hotkey (Ctrl, Alt and Shift by default), the user may be pausing: nothing is released, so wait and ask. With the default hotkey that means only a stuck Windows key can be released for you; a stuck Ctrl, Alt or Shift stays until the user presses and releases it.
- `PasteNotAllowed`: `type_text` with `method: "paste"` into a terminal (type there instead), or the clipboard changed right before its Ctrl+V. Otherwise: the keys or the right or middle click (in a terminal, or anywhere in VS Code and the editors built on it) would paste, and the clipboard holds content you did not put there or copy, and that the user did not let you read; or the keys copy and then paste in one call (`^c^v`); or copy keys sent moments ago have not copied yet: retry shortly or call `get_clipboard` first. Put the text there with `set_clipboard` and paste again, or type it with `type_text`; send a copy and its paste in separate calls (see [clipboard.md](clipboard.md)).
- `StaleCapture`: the point came with a `captureId` (or `space` `window`/`client`), and the captured window moved, resized, closed or was minimized since, or the monitors changed; nothing was sent. Capture again and use the new `captureId` with a point from the new image. `CaptureNotFound`: the `captureId` is unknown, older than 10 minutes or not among the last 32 captures: capture again.
- `HandleMismatch`: the `window` selector's window no longer matched it once the call's turn came (another document or tab, a reused handle); nothing was sent. Find the window again. `InvalidArguments` there means the selector's `titleRegex` took longer than 100 ms on the window's title: use a simpler pattern or `titleContains`.
- `InputBusy`: another call held the input for 30 seconds. Retry when your other calls have finished. The window tools (`focus_window`, move, resize, state, snap, close, the batches, `close_application`, `apply_layout`, `launch_application`, `kill_process`) and `set_clipboard` return it too, as an error result, when they waited 30 seconds; they did nothing.

## Element Actions

`element_action`; nothing was done unless the code says otherwise:

- `ElementNotEnabled`, `ElementOffscreen`, `ElementReadOnly`: the control is disabled, scrolled out of view (`scroll_into_view` first, or `realize` for a row of a long list; a minimized window: restore it) or read-only. `PatternNotSupported`: it has none of the patterns the action needs (`error` lists them): use another action (`click`), `fallback: "mouse"`, or `mode: "type"`; `mode: "type"` and `"paste"` take only a text field (an Edit, or a Document or ComboBox with a writable value), never a list or pane.
- `ElementStale`, `AmbiguousElement`, `ElementNotFound`: stop and find the element again with `find_ui_elements`; never act on a look-alike. `ElementStale` with `refMoved: true`: the ref was moved to a re-created look-alike (see Element refs in [elements.md](elements.md#find)): find it again with `find_ui_elements`, check it, then act. `OperationTimedOut`: the search did not cover the window, so it is not known that only one element matches: narrow the criteria or pass a ref.
- `FocusNotOnElement`: `mode: "type"` could not put keyboard focus in the field, so no keys were sent; click it first or use `mode: "value"`.
- `ActionTimedOut`: the action was sent and has not returned; it may still happen. Read the element before you repeat it. `ActionsPending`: earlier actions wait for open dialogs; answer them first. `ActionFailed`: the app refused it; read the state.
- The input refusals above (`TargetDeniedByPolicy`, `TargetIsAgentHost`, `BlockedByModal`, `PausedByUser`, ...) mean the same for `element_action`, `respond_to_dialog` and `file_dialog`, which act through it.
- `InvalidArguments` naming an argument: every tool refuses an argument it does not declare, naming it, listing its parameters (and the declared name it most likely stands for, when one is close, such as `windowHandle` for `handle`), and does nothing. Use the names of the tool's schema (`controlType`, not `controlTypes`; `element_action` takes no `withinRef`: find the element with `find_ui_elements` `withinRef` and pass its `ref`). A `run_steps` step, a batch item and a launch `placement` (with its `bounds`) or `expectWindow` refuse a member they do not declare too, and for a value of the wrong type, or a whole number out of range, the error says where (`steps[1]`, `placement.bounds`) and what is wrong there; nothing was done.
- `DialogNotFound`: no dialog is in front, or the window you named has none (`file_dialog`: the dialog has no file name box, or `action: "open"` was given a Save As dialog). Wait for it (`wait_for_window`) or list the app's popups (`get_active_popups`). A `respond_to_dialog` press through a window that no modal dialog disables is `DialogNotFound` too, naming its open dialog: read that one and press by its handle ([dialogs.md](dialogs.md#in-the-loop)). `DialogNotCompleted`: `file_dialog` typed the path and pressed the button, but the dialog stayed open (`prompt` holds a question to answer, or a folder was shown). `FileExists`: the file is there and `overwrite` was not true; nothing was replaced.

## Close Results

`close_window`, `close_windows_batch`, `close_application`:

- `PromptShown`: a close reached the window, but the app shows a prompt (`prompt`: title, text, buttons); nothing was answered. Ask the user which button to press, then answer it with `respond_to_dialog`, `handle` set to `prompt.handle` (the prompt's own window, not the window you closed, which its prompt now blocks) and `button`, such as `no` or `cancel`. A prompt of `kind` `inWindowDialog` is drawn inside the window and has no window of its own: use `element_action` on its button. When the error says the prompt's text and buttons could not be read, look at it with `capture_window` before you ask the user.
- `StillOpen`: the window did not close within the wait and shows no prompt: check it, wait longer (`wait_for_window` with `condition: "gone"`), or ask the user before `kill_process`. When the error says its prompt could not be inspected, look at the window with `capture_window` or `get_ui_elements` before you take it as open without a prompt.
- `WaitTimedOut`: `wait_for_window`'s or `wait_for_element`'s condition did not hold within `timeoutMs`; `window` (or `candidates`, the set of windows, or `element` and `lastObservedState`) is what was last seen (still open, not in front, not minimized, old title, still disabled). Look at the screen before you wait again; never act as if the window or control were there.
- `notSent` (a batch item's or `close_application` window's `status`): that window got no close message; its `errorCode` says why (`ProtectedWindow`, `TargetDeniedByPolicy`, `AccessDenied`, `HandleMismatch`, ...). The other windows were still closed.
- `ConfirmationRequired`: closing more than 3 windows, or `force: true` on a protected window, needs the user's yes, and this client cannot ask; nothing was closed. Check the windows with `find_windows`, and pass `confirm: true` only for what the user asked to close. `ConfirmationDeclined`: the user said no.
- `close_application` closes only the windows on the current virtual desktop: `otherDesktopWindows` lists the app's windows on other desktops, which stay open, so `status: "closed"` does not mean the app has ended; `exited` and `runningProcessIds` say whether its processes did.

## Window Tool Refusals

`set_window_bounds`, `set_window_state`, `snap_window` and `move_window_to_monitor` return `NotResponding` when the window's app is hung or does not answer within 5 seconds (the batches say so in the item's `error`, `apply_layout` in `errors`): retry later or ask the user, and check the window first, because a change that timed out can still happen once the app answers. `focus_window` returns `NotResponding`, `Cloaked` (another virtual desktop), `WindowHidden` (a window hidden, for example, in the notification area: show it from the app first, or ask the user), `FocusFailed` (Windows kept another window in front: it protects the window the user last used, see `foregroundLockTimeoutMs` in `get_server_info`) or `TargetDeniedByPolicy`.

## Other Failure Modes

- **A tool is missing:** the user's toolsets, excluded tools or read-only mode leave it out (see [Toolsets](tools.md#toolsets)); `get_server_info` says which. Tell the user instead of working around it.
- **No Windows App Manager tool at all** (not even `get_server_info`): the server did not start. It needs the .NET 10 Desktop Runtime (x64), not just the base .NET Runtime, and the .NET 8 one that releases up to 2.1.0 ran on is no longer enough; `dotnet --list-runtimes` must list `Microsoft.WindowsDesktop.App 10.x`. Tell the user.
- **Coordinates are off:** check `dpiAwareness` in `get_server_info` (it must be `PerMonitorV2`, or `PerMonitor` on Windows before 10 1703), and pass capture points with their `captureId` (or convert them with `imageToScreen`), never with `scaleFactor`.
- **A capture shows nothing useful:** a minimized window fails with `WindowMinimized` (pass `restoreIfMinimized: true`, which restores it without activation and minimizes it again), a hidden one with `WindowHidden`, one on another virtual desktop with `Cloaked`. Read the capture's `warnings`: `ImageBlank` (one solid color: GPU or protected content, or not painted yet), `WindowNotResponding` (copied from the screen, so covering windows show) or `DpiScaledWindow`.
- **A window is not listed:** listings leave out cloaked windows (other virtual desktops), tool windows, untitled windows and shell windows; see the Tips in [windows-and-apps.md](windows-and-apps.md#tips) and [SKILL.md](SKILL.md#tips-for-every-task).
- **A launched app's window is not found** (`launchStatus` `possibleHandoff`, `exitedWithoutWindow` or `timedOut`): the program was started, so never launch it again. Find the window with `find_windows`, or launch with `expectWindow` next time. `awaitingUserConsent` means Windows shows a consent or security prompt (UAC, SmartScreen): only the user may answer it, so ask the user and never click or type into it. `InvalidUri`: percent-encode quotes and spaces in a URI (`%22`, `%20`). `ExecutableNotFound`: the bare name is not installed where the server looks; use the full path. `InterpreterWithArguments` or `ScriptFile`: the server does not run commands or scripts (`cmd`, PowerShell, `python` and the like with arguments, or a `.bat`, `.cmd`, `.ps1`, `.vbs` or `.py` file); ask the user to run it, and never type the command into a terminal instead. `UnsafeChromiumSwitch`: a Chromium, Electron or VS Code switch that runs a command, loads code or opens the program to remote control, refused for any program; for a web page to read or control, use `launch_browser_with_debug`, otherwise ask the user. For VS Code launch `code.exe`, not `code` (a `.cmd` file).
- **`kill_process` refused** (nothing was ended): `CannotTerminateHost`, your own terminal or editor; `ProtectedProcess`, a system or shell process (end a Store app by its own `processId`); `TargetDeniedByPolicy`, a denied app; with `forceKill: true` also when a child process it would end is one of those (the error names it). `ProcessTreeUnreadable` (also without `forceKill`): the process list could not be read to check this; retry, or close without `forceKill`. `ConfirmationRequired`: this client cannot ask the user; pass `confirm: true` only when the user asked to end that process.
- **Input stays paused after `resume_input`:** `ResumeNeedsUser`: this client cannot ask the user, so only the user can resume input, as the error says; tell them. `ResumeDeclined`: the user said no or did not answer, input was paused again while the question was open, or another `resume_input` is still waiting for the answer. Do not call it again on your own: ask the user what to do.
- **The clipboard is refused:** see [clipboard.md](clipboard.md).
